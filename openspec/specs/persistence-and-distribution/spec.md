# Спецификация: Сохранения и поставка

> Статус: DRAFT. Сохранение желательно для MVP; CSV и GitHub Releases ZIP опциональны.

## Requirement: Офлайн-работа

Приложение SHALL выполнять все основные функции без сетевого подключения и SHALL поставлять необходимые каталоги и справочные данные локально.

### Scenario: Запуск без сети
- WHEN пользователь запускает приложение на компьютере без доступа к интернету
- THEN он может создавать эксперименты, использовать локальную энциклопедию и выполнять поддерживаемые расчёты

## Requirement: Сохранение эксперимента

Система SHOULD сохранять конфигурацию эксперимента, пользовательские вещества и реакции в версионируемом локальном формате.

### Scenario: Загрузка несовместимого файла
- WHEN пользователь открывает файл неизвестной или неподдерживаемой версии
- THEN система сообщает о несовместимости и не перезаписывает файл автоматически

## Requirement: Экспорт результатов

Система MAY предоставлять экспорт временных рядов и результатов в CSV.

### Scenario: Экспорт CSV
- WHEN пользователь запускает экспорт результатов
- THEN система создаёт CSV с временной колонкой, заголовками, единицами и выбранными рядами

## Requirement: Windows-сборка

Репозиторий SHALL поддерживать сборку приложения для Windows 10/11 x64. Публикация ZIP-архива в GitHub Releases MAY быть включена как канал распространения.

### Scenario: Запуск Windows-сборки
- WHEN пользователь получает готовый Windows-пакет и распаковывает его
- THEN приложение запускается без установки Godot Editor и без сетевых запросов


## Уточнение хранения и поставки MVP (2026-11-02)

### Requirement: Воспроизводимое сохранение эксперимента
Файл эксперимента SHOULD хранить начальное химическое состояние, условия (T/P/объём), версии схемы/моделей/данных, настройки solver и допуски, дискретные события, расписания потоков, порядок событий и ссылки на пользовательские вещества. Визуальный layout SHALL храниться отдельно от химического состояния.

#### Scenario: Сохранение и перемещение объекта
- WHEN пользователь перемещает объект и сохраняет эксперимент
- THEN layout position сохраняется отдельно
- AND перемещение не меняет химическое состояние или simulation hash

#### Scenario: Replay после загрузки
- WHEN пользователь загружает эксперимент и запускает детерминированный replay
- THEN используются сохранённые версии моделей/данных и solver settings
- AND несовместимые версии выявляются явно

### Requirement: Офлайн provenance
Встроенный каталог SHALL работать без сети и сохранять provenance, лицензионный статус и область применимости каждого встроенного свойства.

#### Scenario: Отсутствует сеть
- WHEN устройство отключено от сети
- THEN поиск каталога, карточки свойств, hazard completeness и поддерживаемые расчёты доступны офлайн

### Requirement: Ограничение лицензирования
Данные с неизвестными лицензиями/условиями повторного использования SHALL NOT автоматически включаться в распространяемый ZIP-пакет.

#### Scenario: Проверка пакета
- WHEN формируется redistributable build
- THEN включённые данные проходят allowlist/licensing check
