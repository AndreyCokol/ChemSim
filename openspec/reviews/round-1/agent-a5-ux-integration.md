# Раунд 1 — ревью A5: Godot UX & Integration

Статус: профильное ревью завершено.

## Вывод
Пользовательский интерфейс должен явно различать исходные данные, состояние расчёта, численную ошибку и уровень научной применимости. Не сводить их к одному зелёному значку «точно».

## Критические замечания
1. **Статус результата должен быть составным.** Предлагаемые поля: data_quality, model_validity, numerical_status, completeness, warnings. Итоговые labels: «Проверенный режим», «Приближённая модель», «Пользовательские данные», «Неполные данные — запуск запрещён», «Численная ошибка». Это не статистическая вероятность точности.
2. **Блокировка запуска должна объяснять точные отсутствующие входы.** Например: нет k(T), Ea или K нужного basis; нет давления; температура вне диапазона; отсутствует объём для mol/L.
3. **Температурный UI.** Отображать T в °C и K, давление в выбранных единицах, модель газа, режим изотермический/тепловой. Не предлагать газовый расчёт без необходимых условий.
4. **График температуры.** До появления энергетической модели показывать заданную постоянную T с явной подписью «изотермическая модель», не изображать нагрев от реакции.
5. **Rewind.** Различать «перемотка по сохранённой истории» и «пересчёт от начала». Показывать версию данных и модели, чтобы пользователь видел, почему старый эксперимент может быть пересчитан иначе.
6. **Визуальные координаты.** Отделить layout_position от chemical_state; перемещение не должно инвалидировать химический результат или создавать simulation event.
7. **Сохранение.** Сохранять модельные входы, события, версии базы и solver settings; UI layout отдельно, чтобы перенос объекта не менял вычислительный replay.
8. **Безопасность.** Энциклопедические предупреждения видны до запуска эксперимента, но UI не позиционирует справку как инструкцию по безопасному обращению.

## Предлагаемые состояния UX
- Ready — все обязательные входы для выбранного расчёта заданы.
- Blocked — отсутствуют параметры/данные или режим вне применимости.
- Running / Paused / Stepping.
- Completed.
- Failed — solver/model error, с диагностикой.
- ResultsWithWarnings — расчёт завершён, но применялись явно отмеченные приближения.

## Приёмочные UX-тесты
- Перемещение визуального объекта не меняет simulation hash.
- Переключение UI units не меняет canonical SI state.
- Blocked state перечисляет все причины.
- Пользовательские данные видны на графике и в карточке результата.
- Rewind history и recompute приводят к согласованным состояниям в пределах tolerance.
- Отсутствующая hazard data отображается как «неизвестно», не «безопасно».
