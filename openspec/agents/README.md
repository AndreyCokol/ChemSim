# Командная работа ChemSim: 5 специализированных агентов

## Цель

Разделить проект на пять независимых областей, чтобы агенты могли параллельно исследовать и реализовывать систему без конфликтов в химической модели и исходном коде.

## Роли и владение

| ID | Роль | Основная зона ответственности | Основные артефакты |
|---|---|---|---|
| A1 | Chemistry Data & Domain | Сущности веществ, справочные данные, единицы, происхождение данных | domain schema, substance catalog, data validation |
| A2 | Equation Parser & Balancer | Парсер химических формул/уравнений, стехиометрия, балансировка | grammar, parser, balancer, parser tests |
| A3 | Aqueous Chemistry & Equilibrium | Ионные процессы, pH, кислотно-основные равновесия, растворимость и осадки | equilibrium model, aqueous chemistry tests |
| A4 | Kinetics & Numerical Solver | Кинетика, Аррениус, обратимые реакции, открытые/закрытые системы, интегратор | solver contract, kinetics engine, numerical benchmarks |
| A5 | Godot UX, Visualization & Integration | Godot UI, графики, координаты, управление временем, сохранения, сквозная интеграция | scenes/UI, chart adapter, persistence, integration tests |

## Правила параллельной работы

1. Сначала каждый агент выполняет исследование и обновляет принадлежащую ему спецификацию. Код не пишется до утверждения OpenSpec change владельцем.
2. Каждый агент читает общий design.md, config.yaml и свой промт.
3. Агент не меняет чужие файлы, публичные типы или контракты без согласования с интегратором.
4. Не создавать дублирующие модели вещества, реакции, единиц, ошибок или времени.
5. Любое химическое значение должно иметь единицы, источник и условия применимости либо явный статус «неизвестно/оценка».
6. Отделять стехиометрические коэффициенты от кинетических порядков.
7. Все вычисления должны быть воспроизводимы и проверяемы; UI не должен содержать химические формулы расчёта.
8. При блокирующем противоречии агент документирует варианты и останавливает зависимую реализацию, а не угадывает.
9. Каждый агент выдаёт: изменённые документы, решения, открытые вопросы, тестовую матрицу, зависимости и риски.
10. Интегратор сводит контракты и запускает общие проверки; владелец продукта утверждает спецификацию.

## Порядок выполнения

- Раунд 1 (параллельно): A1–A4 исследуют предметную/математическую модель; A5 исследует UX и интеграцию, не создавая фиктивных API.
- Раунд 2: согласование общего schema/units/reaction/state/result contract.
- Раунд 3: OpenSpec review и утверждение.
- Раунд 4: отдельные implementation-ветки с неизменяемыми контрактами.

Профильные ревью по ролям A1–A5 и интегрированный отчёт находятся в openspec/reviews/round-1/.

- agent-a1-data-domain.md

Ревью выявило блокирующие решения по basis равновесных констант, тепловой модели, границам активности/газовых моделей, лицензированию данных и минимальной грамматике парсера. Реализация остаётся заблокированной до утверждения этих решений владельцем.


## Уточнение scope после решений владельца (2026-11-02)

Промпты A1–A5 синхронизированы с текущим MVP и являются заданиями на исследование/спецификацию, а не разрешением писать код. Обязательные общие границы:
- водные растворы только разбавленные, идеальное приближение или явно поддерживаемая модель активности;
- газы только идеальные: PV=nRT + закон Дальтона;
- MVP изотермический; не-изотермическая модель отложена;
- мгновенное идеальное смешивание доступно, конечное смешивание отложено;
- непрерывные потоки только постоянные/кусочно-постоянные;
- плоское воксельное поле визуальное, отдельная панель расчёта, отдельные окна графиков/подробностей;
- численные benchmark fixtures не утверждены до проверки источников, условий, basis, uncertainty и допусков;
- реализация запрещена до явного утверждения владельцем OpenSpec baseline.

## Текущий порядок
1. A1–A5 независимо проверяют свои спецификации и готовят контракты/отчёты.
2. Интегратор согласует общие DTO, единицы SI, версии схем, ошибки, события и replay.
3. Интегратор закрывает противоречия и обновляет OpenSpec.
4. Владелец утверждает baseline.
5. Только после этого создаются implementation-задачи.
