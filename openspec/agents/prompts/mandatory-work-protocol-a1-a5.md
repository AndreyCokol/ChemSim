# ОБЯЗАТЕЛЬНЫЙ ПРОТОКОЛ РАБОТЫ ДЛЯ AGENT A1–A5 (ChimistrySim)

Данный протокол обязателен для всех агентов проекта ChimistrySim (репозиторий ChemSim): A1, A2, A3, A4 и A5. Соблюдай его перед новой рабочей сессией, при продолжении ранее начатой задачи и перед следующим этапом разработки.

## 1. Сверка с исходным промптом

1. Найди и прочитай первоначальный индивидуальный промпт из `openspec/agents/prompts/` и дополнительные инструкции.
2. Установи роль, ID, полный перечень обязанностей, границы ответственности, зависимости и критерии завершения.
3. Не расширяй зону ответственности и не изменяй утверждённые решения владельца или других агентов.
4. Если исходный промпт недоступен, не восстанавливай его по предположениям: зафиксируй BLOCKED.

## 2. Аудит ранее выполненной работы

До написания кода проверь структуру проекта, существующие файлы, свои коммиты, открытые PR и замечания к ним, Issues, CI/CD, тесты, документацию, архитектурные решения, незавершённые задачи, дефекты и технический долг. Не считай задачу выполненной только по прошлому отчёту.

Для каждой задачи установи фактический статус по коду, тестам, документации и GitHub:
- **DONE** — завершена и проверена;
- **PARTIAL** — выполнена частично;
- **IN_PROGRESS** — выполняется;
- **BLOCKED** — есть внешняя зависимость;
- **NOT_STARTED** — не начата;
- **NEEDS_REVIEW** — реализация есть, требуется проверка.

При обнаружении дефекта сначала оцени влияние и исправь в рамках своей ответственности.

## 3. Индивидуальный план задач

После аудита, **до реализации**, составь актуальный план в рамках индивидуального промпта. Для каждой задачи укажи: ID/название, конкретное действие, обоснование, затрагиваемые файлы/компоненты, зависимости и ответственных, приоритет, критерии готовности, способ проверки, текущий статус.

Приоритеты: **P0** — критический блокер; **P1** — обязательно до тестового запуска; **P2** — для полноценной функциональности; **P3** — улучшения.

Отдельно выдели незавершённые задачи, обнаруженные дефекты, необходимые для MVP задачи, откладываемые задачи и внешние блокеры. Чужие задачи не включай как собственные обязательства — указывай владельца и способ взаимодействия.

## 4. Сверка с другими агентами

Перед реализацией проверь зависимости A1–A5: интерфейсы, DTO/схемы, имена и типы полей, единицы измерения, enum/статусы, версии схем, обработку ошибок и передачу результатов.

При несовместимости: (1) зафиксируй конкретный случай, (2) определи ответственного, (3) предложи исправление, (4) сообщи владельцу, (5) не меняй чужой контракт без согласования.

## 5. Порядок выполнения

После пунктов 1–4 выполняй P0 → P1 → P2 → P3. Соблюдай архитектуру, не дублируй функциональность, не выдавай временные решения за готовые, не отключай тесты ради CI, не скрывай ошибки, добавляй тесты, сохраняй требуемую совместимость и фиксируй изменения **в своей рабочей ветке**. Перед изменением чужого модуля согласуй его с владельцем. Соблюдай существующие правила GitHub по закреплению/lease задач, если они предусмотрены проектом.

**Важное ограничение:** исходные индивидуальные промпты требуют сначала исследования/спецификации и утверждения владельцем перед реализацией. Настоящий протокол не отменяет этот gate. Если утверждения нет, выполняй только разрешённую подготовительную работу и фиксируй блокер реализации.

## 6. Проверка работы

После каждого значимого этапа проверь файлы, запусти релевантные тесты, проверь интеграционные зависимости и совместимость контрактов, CI/CD, зафиксируй изменения в Git и обнови статусы задач. Не присваивай DONE без подтверждения.

## 7. Обязательный отчёт до реализации

Перед каждой сессией выдай краткий отчёт:

### Agent [ID] — предварительный аудит
1. **Моя роль:** обязанности из индивидуального промпта.
2. **Что уже сделано:** задачи и ссылки на файлы, коммиты, PR или тесты.
3. **Что не завершено:** незакрытые и частичные задачи.
4. **Обнаруженные проблемы:** дефекты, несовместимости, блокеры.
5. **План текущей работы:** приоритеты, действия и критерии готовности.
6. **Зависимости:** другие агенты и необходимые решения.
7. **Ближайшая цель:** проверяемый результат этой сессии.

После отчёта приступай к доступной задаче, если нет критического блокера или запрета на реализацию.

## 8. Непрерывная работа

После каждого «Продолжай работу»: перечитай индивидуальный промпт; проверь актуальное состояние и итоги прошлой сессии; обнови остаток задач; выбери наиболее приоритетную доступную; выполни её в рамках разрешённой фазы; зафиксируй проверяемый результат. Не повторяй выполненное без необходимости. Не объявляй модуль или проект готовым без проверки. Не ограничивайся отчётами.

## 9. Главная цель

Полностью реализовать **свою** зону ответственности в рамках ChimistrySim: соответствие промпту, полнота, качество кода, тесты, совместимость, критерии готовности и исправление дефектов. Приоритет — запускаемая тестовая версия (MVP), а не расширение функциональности в ущерб блокерам запуска.

**Протокол обязателен для A1–A5. Индивидуальный промпт, решения владельца и согласованные контракты сохраняют силу.**
