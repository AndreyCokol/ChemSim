# A4-BENCH-01 — воспроизводимая матрица benchmark для кинетики и solver

Статус: план benchmark, не результаты измерений. Область текущей реализации: закрытая, изотермическая, постоянный объём; необратимые степенные законы; явный Dormand–Prince 5(4). Документ не утверждает, что текущий solver уже прошёл все перечисленные испытания.

## Цели и правила

1. Проверять отдельно физическую модель, точность интегрирования, устойчивость и производительность.
2. Каждая запись benchmark должна хранить: ID случая, уравнения/параметры с единицами, начальное состояние, объём, временной горизонт, сетку output times, rtol, atol, лимиты шага, reference method/version, ожидаемые инварианты, фактический статус, ошибки, число принятых/отклонённых шагов, RHS evaluations и wall-clock.
3. Числа ниже — синтетические математические fixtures, а не справочные химические данные.
4. Все сравнения выполняются в double precision как минимум; reference для жёстких случаев должен быть независимым stiff solver (например, CVODE BDF или Radau) с более строгими допусками. Версию, настройки и контрольный файл reference фиксировать.
5. Не сравнивать wall-clock между разными машинами без фиксации CPU, OS, runtime, build configuration и повторов. Основные показатели — численные; время является вспомогательным.

### Точное определение жёсткого Robertson fixture

Для концентраций x,y,z в mol/m³:

- dx/dt = -0.04 x + 10⁴ yz
- dy/dt = 0.04 x - 10⁴ yz - 3·10⁷ y²
- dz/dt = 3·10⁷ y²

Начальное состояние (1,0,0). Сумма x+y+z сохраняется. Эта fixture намеренно содержит очень быстрый и медленный масштабы времени; её назначение — показать границы явного RK45, а не требовать от него гарантированного завершения на любом горизонте.

## Матрица допусков и сходимости

Для B01–B04 и B06 прогнать как минимум:

| Run | rtol | atol (mol для amount-state) | Назначение |
|---|---:|---:|---|
| T1 | 1e-4 | 1e-8 | грубая контрольная точка |
| T2 | 1e-6 | 1e-10 | текущий default-порядок |
| T3 | 1e-8 | 1e-12 | строгая проверка |
| T4 | 1e-10 | 1e-14 | проверка предела double precision / стоимости |

atol должен масштабироваться с единицами и характерным масштабом fixture; приведённая колонка — только baseline для молярного state. Для Robertson, где состояние задаётся в mol/m³, абсолютный допуск указывать в mol/m³ и выбирать отдельно, а не механически копировать молярный atol.

Критерии:
- Ошибка относительно аналитического/reference решения должна уменьшаться при ужесточении допусков до ожидаемого плато округления.
- Не требовать строго монотонного уменьшения каждого отдельного output-компонента: адаптивная сетка и округление могут дать небольшие немонотонности. Сравнивать нормированную ошибку всего профиля и финальную ошибку.
- Сравнение проводить в общих фиксированных output times; внутренние adaptive steps не должны влиять на точки сравнения.
- Заранее зафиксировать критерии успеха: B01–B04 должны достигать заданной аналитической точности без отрицательных количеств; B05 обязан либо совпасть с reference в заданном допуске, либо завершиться диагностируемым ограничением (например, бюджет/step underflow), но никогда не публиковать недостоверный профиль как успешный.

## Проверки физической и численной корректности

Для каждого закрытого fixture:
- Позитивность: все опубликованные количества конечны и >= 0; промежуточные отрицательные стадии не клиппируются, а отклоняются.
- Баланс: проверять заранее заданные линейные инварианты (например, A+B, A+B+C, X+Y+Z) на каждом output sample.
- Размерности: rate constants соответствуют сумме кинетических порядков; stoichiometric coefficients не подменяют orders.
- Воспроизводимость: повторный запуск с идентичными параметрами и сборкой даёт совпадающий профиль в пределах выбранного допуска.
- Ошибочные режимы: нулевой реагент для положительного порядка, rate=0, очень малые/большие величины, недостижимый шаг, отмена и исчерпание бюджета дают детерминированный статус и диагностику.

## Метрики производительности

Обязательно сохранять:
- wall-clock elapsed time и throughput (simulated seconds / wall-clock second);
- accepted steps, rejected steps, RHS evaluations;
- средний и максимальный accepted step, если solver начнёт экспортировать эти диагностические величины;
- число output samples, пиковую память (если измеряется надёжным profiler);
- конечную нормированную ошибку и максимальную ошибку по профилю.

Проводить минимум 5 прогонов после одного warm-up; публиковать медиану и диапазон, не только лучший результат. Сравнивать solver-ы только при одинаковых моделях, начальных данных, output times и критериях точности. Не использовать wall-clock как единственный критерий качества.

## Когда выбирать или разрабатывать implicit solver

Не выбирать BDF/Radau только потому, что он «быстрее» на одном примере. Решение об implicit solver обосновывается совокупностью доказательств:

1. B05 и дополнительные жёсткие fixtures регулярно требуют чрезмерно малых явных шагов, превышают бюджет или не завершаются в целевом горизонте при разумной точности.
2. Независимый BDF/Radau reference проходит те же fixtures с контролируемой ошибкой, positivity и conservation checks.
3. На одинаковой точности implicit method показывает устойчивое преимущество по вычислительной стоимости на целевом наборе, а не только на одном stiff кейсе.
4. Проверены переходные режимы, где жёсткость меняется во времени, а также малые/нулевые компоненты и conservation drift.
5. Есть обоснованный план nonlinear solve, Jacobian strategy, failure diagnostics и воспроизводимых тестов.

До получения этих данных текущий RK45 остаётся baseline для нежёстких систем. Система должна явно документировать, что explicit RK45 не гарантирует эффективность или завершение на жёстких задачах; успешность B01–B04 не является доказательством пригодности для B05.

## Протокол публикации результатов

Для каждого запуска публиковать короткий JSON/CSV artifact со схемой: case_id, solver, solver_version, runtime, os_cpu, rtol, atol, status, final_error, max_profile_error, max_conservation_drift, min_state, accepted_steps, rejected_steps, rhs_evaluations, elapsed_ms, reference_id. Не добавлять fabricated reference values или результаты производительности в этот документ: заполнить их только после фактического прогона.

## Текущие ограничения и нецели

- В текущей реализации нет BDF/Radau, Jacobian, stiffness detection или автоматического переключения.
- Нет температурной зависимости Аррениуса, обратимых реакций, открытых потоков и событий.
- Этот benchmark plan не является разрешением реализовывать перечисленные функции и не меняет границы A4.
- Текущий A4 codebase интегрирует количества в mol; Robertson задаётся в концентрациях, поэтому перед тестовым прогоном надо преобразовать n_i = c_i V и согласовать atol с единицами state.
