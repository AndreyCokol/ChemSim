## Правило разработки

Для каждой функциональности сначала фиксируются требование и критерий приёмки, затем проектируется изменение, затем пишутся тесты и реализация. Изменение поведения без соответствующего изменения спецификации считается незавершённой работой.

## Статус

- Версия спецификации: 0.1.0.
- Статус: baseline для MVP, подлежит уточнению при ревью.
- Код приложения намеренно не включён в этот первый этап.
